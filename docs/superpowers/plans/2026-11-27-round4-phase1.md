# Round 4 Phase 1 (Tools) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw mode and the Views grid get free lines (any snap point to any snap point) and an arc tool (valid isometric arcs only); nothing else changes.

**Architecture:** Points get exact √2 parts so the 45° points of arcs have exact keys. Lines stay a list of `SegKey` pieces split at lattice points (old unit and diagonal keys stay valid). Arcs are a new `arcs` list in `Drawing`, stored as single-eighth pieces (`ArcKey`), like unit line pieces. `IsoGrid` gets a `free` option; Shadows does not set it and does not change.

**Tech Stack:** TypeScript, Vite, Vitest (+ jsdom), Playwright. No new dependencies.

**Spec:** `docs/2026-11-27-round4-design.md` (sections "Draw tools", "Phases" item 1).

## Global Constraints

- Web version only; tests first for `src/core`; one commit per task (`CLAUDE.md`).
- No new dependencies.
- All checks stay exact: no float tolerance in keys or comparisons. Coordinates are halves and quarters (exact in floats); √2 is applied only when a point turns into screen units.
- Old saved drawings (unit lines and round 3 one-cell diagonals such as `0:0|1:1`) must load, render and erase unchanged.
- Reverse, Nets and Shadows do not change. Shadows keeps the 3-direction line snap.
- Backup version stays 3 in this phase (version 4 comes with phase 4). Backups with and without `arcs` import.
- Arcs: radius ½ or 1 (cells), in one of the 3 face planes, always a run of whole eighths.
- Snap points: grid dots; edge midpoints (Draw mode only in this phase — Views gets them in phase 3, so cube puzzles do not get harder to hit); the eighth points of every drawn arc. Extra snap points show only while the line or arc tool is active.
- Work on branch `round4-tools`; merge to `main` and push (no PR) when the last task passes. Push deploys to GitHub Pages.

## Review Focus

1. A Views cube puzzle drawn with the free line tool still gives exactly the answer's unit keys, so a correct drawing is marked correct (test in Task 5).
2. Two arc taps on points that no valid arc joins: nothing is added, nothing breaks, the second tap becomes the new first point (test in Task 5).
3. Undo after a dot drag gives back the first arc; a second undo removes it; arc pieces that were in the drawing before the arc stay after a replace (tests in Task 3).
4. A backup with arcs imports and round-trips; an old backup without `arcs` still imports (test in Task 3).
5. The eraser near an arc and a line takes only the nearer one (test in Task 5).

### Task 2: Arcs core

**Files:**
- Create: `src/core/arcs.ts`
- Test: `tests/core/arcs.test.ts`

**Interfaces:**
- Consumes: `Pt`, `ptKey`, `parsePt`, `toUV`, `samePt` (Task 1).
- Produces:
  - `type Plane = 'x' | 'y' | 'z'` (the plane's normal: `z` top, `y` front, `x` side).
  - `type Arc = { plane: Plane; c: Pt; r: 0.5 | 1; k0: number; n: number }` — starts at eighth `k0` (0–7), runs `n` eighths (1–8) counter-clockwise in the plane basis.
  - `type ArcKey = string` — one eighth: `` `A${plane}|${ptKey(c)}|${r}|${k}` `` with `k` in 0–7.
  - `isArcKey(k: string): boolean` (starts with `A`).
  - `eighthPoint(plane: Plane, c: Pt, r: 0.5 | 1, k: number): Pt`.
  - `arcPieces(a: Arc): ArcKey[]`.
  - `pieceEnds(k: ArcKey): [Pt, Pt]` (eighths `k` and `k+1`).
  - `arcPolyline(k: ArcKey, steps?: number): [number, number][]` — screen points along one eighth, `steps` default 6 (7 points).
  - `arcMid(a: Arc): [number, number]` — screen point at angle `(k0 + n/2)·45°`.
  - `arcsThrough(p: Pt, q: Pt): Arc[]` — every valid arc with ends `p` and `q`, ranked.
  - `arcSnapPoints(keys: ArcKey[]): Pt[]` — unique end points of all pieces.

Values the tests do not fix:
- Projected plane basis: X → `{t:1, m:0}`, Y → `{t:-1, m:1}`, Z → `{t:0, m:1}`. Plane `z` uses (E1, E2) = (X, Y); `y` uses (X, Z); `x` uses (Y, Z).
- Eighth `k` is at angle `k·45°`: `c + r(cos·E1 + sin·E2)`. For odd `k` the offset goes into `rt`/`rm` as `(r/2)(±E1 ± E2)`; for even `k` into `t`/`m`.
- `arcsThrough`: for each plane, `r`, and eighth `i`, the centre is `p − offset(i)`; keep it only if it is rational with coordinates in ½ℤ; for each `j ≠ i` with `c + offset(j) == q` (exact), add both arcs (`i`→`j` and `j`→`i`). Rank **(builder's call)**: fewer eighths first, then the arc whose midpoint is lower on screen, then plane order `z`, `y`, `x`.

### Task 5: Free line and arc tools on the grid

**Files:**
- Modify: `src/ui/grid/IsoGrid.ts`, `src/ui/grid/grid.css`
- Test: `tests/ui/grid.test.ts`

**Interfaces:**
- Consumes: `snapFree`, `snapPoint`, `arcsThrough`, `arcMid`, `arcSnapPoints`, `addArc`, `replaceArc` (Tasks 1–3).
- Produces:
  - `type Tool = 'line' | 'arc' | 'freehand' | 'fill' | 'erase'`.
  - `IsoGridOpts.diagonals` is removed; new `free?: { half: boolean }`. Without `free` the grid works exactly as now (Shadows). With `free`: the line tool uses `snapFree` with `extra = arcSnapPoints(drawing.arcs)`, and the arc tool works (below).
  - New layer `g-snap` (above `g-lines`): small circles at the extra snap points (half points in the visible area when `half`, plus arc eighth points), drawn only while `free` is set and the tool is `line` or `arc`. `render()` redraws it, so screens call `grid.render()` after a tool change.
  - New layer `g-handle`: the arc dot.

Arc tool behaviour (end point of each stroke counts as the tap):
1. First tap: snap the point; show a marker in `g-prev`.
2. Second tap on a different point: `arcsThrough(first, second)`. Empty: the second point becomes the new first point. Else: `added = editor.addArc(cands[0])`, keep `{ p, q, arc, added }` as the last arc and show the dot at `arcMid(arc)`. Same point again: drop the first point.
3. A stroke that starts within 0.4 grid steps of the dot drags it: while moving, preview (in `g-prev`) the candidate of `arcsThrough(p, q)` whose `arcMid` is nearest the finger; on release, if it differs, `added = editor.replaceArc(added, chosen)`.
4. Any other stroke, a tool change or `render()` after undo/redo/clear that leaves the last arc's pieces out of the drawing hides the dot. A second finger (`cancel`) drops the first point and any drag preview.

Eraser: the nearest piece among lines (`segDist`) and arc pieces (distance to the `arcPolyline` segments) within `ERASE_DIST`; same one-per-point rule as now.
